# 议题追踪 · 活状态（跨会话连续性的"读得到的状态"）

> 这是 Heart 工作流的**记忆中枢**。会话记录（`data/sessions/*`）是"发生过什么"的流水账；本文件是"现在正开着什么、上次到哪、什么时候该跟进"的**活状态**——每次开场必读，每次收场必更。
> 内容比业务数据更私密，不外传。事实以 `Akagavin` 画像为准；本文件只写心态层，推测标 `🔸`。

---

## 0. 它在工作流里的位置（闭环）

```
开场 ──► 读本文件（在追踪什么？有没有到期跟进？）
      ──► 读最近 1-2 条会话记录（上次具体谈了什么）
      ──► 扫安全信号 → 加载画像 → 精确共情 → 疏导/分析
收场 ──► 写会话记录（data/sessions/）
      ──► 回到本文件：开新议题 / 更新进展 / 合上已解决的 / 记跟进约定
```

> 没有"读本文件"这一步，会话就是失忆重启，模式追踪名存实亡。**它是闭环里那个唯一让状态被读到的环节。**

---

## 1. 维护协议（Agent 每次会话执行）

**开场（读）：**
1. 先看 `[Heart 同步]` 输出：若 WARN，本次所有耦合现实坐标的心理判断都要标明数据非实时，并按 AGENT.md §3.2 降级。
2. 若触及 T01 / 交易 / 持仓 / 纪律，先读 `data/Notion动态真值核对.md` 并只读核对 Notion 当前行；有 `持仓中` 就按仓位管理模式处理。
3. 扫 §3 活跃议题表：有没有 `跟进到期日` ≤ 今天的？有就在本次主动提起（温和，不审问）。
4. 看每条议题的 `上次进展`，避免重复提问、避免把已确认的当未知。
5. 若本文件与画像/会话记录冲突，以更晚的真实会话为准，并在本文件改正。

**收场（更新，按需做下列动作）：**
- **开新议题**：会话中浮现一个需要跨次跟进的心理议题 → 在 §3 加一行，分配 `T##` 编号。
- **更新进展**：已存在的议题有新进展 → 改 `上次进展` + `上次触碰` 日期 + 必要时调 `风险`。
- **合上议题**：议题已解决/不再活跃 → 移到 §4，写一句"如何收的"。
- **记跟进**：约定了下次跟进 → 填 `跟进到期日`。没有明确约定就留空，不硬造。
- **状态分类**：每条标清是 `清醒痛苦`（高认知者的合理张力，**不病理化**）还是 `失调信号`（需关注/评估）还是 `待澄清`——呼应 AGENT.md §4 的核心判断。

> 维护原则：**宁缺毋造**。没真实进展就不编进展；没明确约定就不填跟进日；推测一律标 `🔸`。

## 2. 议题状态字段说明

| 字段 | 含义 |
|---|---|
| `ID` | `T##`，跨会话稳定不变，会话记录里引用它 |
| `议题` | 一句话命名（把模糊情绪命名为可处理的问题） |
| `类型` | 清醒痛苦 / 失调信号 / 待澄清 |
| `起始` | 首次在会话中打开的日期 |
| `上次进展` | 最近一次的状态/推进，一句话 |
| `上次触碰` | 最近处理日期 |
| `跟进到期日` | 约定的下次跟进日；无约定留空 |
| `风险` | 无 / 关注 / 需专业评估 / 紧急 |
| `关联会话` | `data/sessions/` 里的文件名 |
